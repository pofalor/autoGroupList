# Архитектура GroupListNet

## Общее описание

GroupListNet помогает старосте вести учёт посещаемости учебной группы. Бот рассылает студентам
уведомления о начале пар, собирает отметки «я на паре», после дедлайна присылает старосте список
отметившихся и по желанию переносит отметки на сайт вуза.

Бот работает одновременно в двух мессенджерах — телеграме и ВКонтакте. Студент отмечается там,
где ему удобнее, и может привязать оба аккаунта к одной записи в группе.

## Состав решения

| Проект | Назначение |
| --- | --- |
| `GroupListNet` (`GroupListNet.Web.Api`) | Хост: ASP.NET Core, точка входа, конфигурация, применение миграций |
| `GroupListNet.Core` | Вся бизнес-логика: боты, фоновые задачи, сущности, репозитории, парсеры |
| `GroupListNet.Utils` | Расширения общего назначения |
| `GroupListNet.Core.Tests` | Модульные тесты (xUnit) |

Внешние зависимости: `Telegram.Bot`, `VkNet`, EF Core с `Npgsql`, AutoMapper, NLog. Работа с сайтом
вуза закрыта приватным пакетом `GroupListNet.Addons` (интерфейс `IMarker`).

Веб-части как таковой нет: `HomeController` отдаёт страницы шаблона ASP.NET, а `SosController`
и `SosService` — незаполненные заготовки без единого метода. HTTP-хост нужен только чтобы держать
процесс с фоновыми задачами и применять миграции.

## Запуск приложения

`GroupListNet/Program.cs`:

1. Поднимает NLog по `GroupListNet/config/nlog.config`.
2. Регистрирует `ApplicationDbContext` на PostgreSQL и зовёт `AddCore()` —
   `GroupListNet.Core/src/Installers/CoreInstaller.cs`, единая точка сборки DI: сервисы,
   транспорты мессенджеров, фоновые задачи, репозитории и приватный пакет отметки на сайте.
3. Применяет миграции (`Database.MigrateAsync`) и зовёт `ILeaderService.SyncMainLeadersAsync()`,
   чтобы выдать права старостам, заданным в конфиге.
4. Запускает хост — дальше всё происходит в фоновых задачах.

## Модель данных

`GroupListNet.Core/src/Entities`. Все сущности наследуют `PersistentEntity`: `Id`,
`ObjectCreateDate`, `ObjectEditDate`, `Version` (`rowversion`) и `IsDeleted`.

| Сущность | Смысл |
| --- | --- |
| `Student` | Студент группы: ФИО, номер в списке, `TelegramId`, `VkId`, подгруппа |
| `Leader` | Ссылка на студента с правами старосты |
| `Subject` | Учебный предмет |
| `Schedule` | Занятие: предмет, время начала и конца, тип, аудитория, здание, подгруппа и либо день недели с чётностью, либо конкретная дата |
| `Attendance` | Отметка студента на занятии в конкретный день |
| `Notification` | Факт уведомления: тип, мессенджер, адресат, ссылка на занятие, статус доставки |
| `GroupSettings` | Одна запись с настройкой «делится ли группа на подгруппы» |

Общие правила:

- **Удаление везде мягкое** — проставляется `IsDeleted = true`, строки остаются в базе.
  Глобальных фильтров (`HasQueryFilter`) в `ApplicationDbContext` нет, поэтому каждый запрос
  решает сам, показывать архив или нет. На этом держится сборка отчёта за прошедший день.
- Имена колонок — `snake_case`, задаются в `src/DataAccess/EntityConfiguration`;
  общая часть — в `BaseEntityConfiguration`.
- `ApplicationDbContext` в `SaveChanges` сам проставляет `ObjectCreateDate` и `ObjectEditDate`.
- Доступ к данным — через репозитории (`src/DataAccess/IReposetories` и `Repositories`)
  поверх общего `Repository<T>`. Миграции лежат в `GroupListNet.Core/Migrations`.

## Слои бота

Логика бота одна на все мессенджеры, различия API спрятаны в транспорт.

1. **Транспорт** — `src/Bot/IMessengerClient.cs` и реализации `TelegramMessengerClient`
   и `VkMessengerClient` в `src/Bot/Clients`. Умеют отправить сообщение, изменить его, убрать
   кнопки и ответить на нажатие. Ошибки приводятся к общему `MessengerSendException`
   с признаком «повторять бессмысленно».
2. **Логика команд** — `src/Bot/BotUpdateHandler.cs`. Транспорт приходит параметром, поэтому
   ответ всегда уходит туда, откуда пришло сообщение. Работает с нейтральными моделями
   `BotMessage`, `BotCallback`, `BotKeyboard` из `src/Bot/Models`.
3. **Приём обновлений** — `TelegramBotBackgroundJob` (long polling телеграма) и
   `VkBotBackgroundJob` (Bots Long Poll ВКонтакте). Обе задачи только переводят обновления
   в общие модели и зовут обработчик. Задача не запускается, если её мессенджер не настроен.
4. **Отправка уведомлений** — `NotificationSenderBackgroundJob` проходит по всем настроенным
   мессенджерам и забирает неотправленные уведомления своего канала.

Состояние диалога (ожидание расписания или списка группы от старосты) обработчик держит в памяти,
ключом служит пара «мессенджер + айди пользователя» — иначе числовые айди разных мессенджеров
могли бы совпасть. При перезапуске такое ожидание теряется, команду нужно повторить.

## Фоновые задачи

`GroupListNet.Core/src/BackgroundJobs`, все — `BackgroundService`. Задачи приёма сообщений ждут
событий от мессенджера, остальные просыпаются раз в минуту — кроме переноса на сайт, у него
свой интервал из конфига.

| Задача | Что делает |
| --- | --- |
| `TelegramBotBackgroundJob` | Принимает сообщения и нажатия из телеграма |
| `VkBotBackgroundJob` | То же для ВКонтакте; при обрыве Long Poll переподключается |
| `StudentScheduleBackgroundJob` | Заводит уведомления о начавшихся парах |
| `LeaderBackgroundJob` | После дедлайна заводит отчёт старосте |
| `NotificationSenderBackgroundJob` | Рассылает неотправленные уведомления |
| `AttendanceSyncBackgroundJob` | Переносит отметки на сайт; не стартует, если это выключено |

## Уведомления

Таблица `notifications` работает как исходящая очередь: задачи-производители кладут в неё запись,
`NotificationSenderBackgroundJob` её забирает и помечает `IsSent`. Если отправить нельзя навсегда
(бот заблокирован, сообщения от сообщества запрещены), в `ErrorMessage` пишется причина и запись
больше не берётся в работу.

**Текст сообщения в базе не хранится.** Лежит только сам факт уведомления, а содержимое собирает
`src/Bot/NotificationMessageBuilder.cs` в момент отправки:

- напоминание о паре — из связанного `Schedule` и его `Subject`, кнопка «Я на паре» получает
  данные `attend_{studentId}_{scheduleId}`;
- отчёт старосте — тем же `src/Entities/Utils/LeaderListFormatter.cs`, который отвечает
  на команду `/list`.

Отчёт собирается за дату уведомления и берёт отметки через
`IAttendanceRepository.GetAttendanceForReportAsync` — отдельный запрос **без условия на
`IsDeleted`**. Это важно: между созданием отчёта и его отправкой староста может перезалить
расписание или список группы, отметки уедут в архив, и без такого запроса отчёт превратился бы
в «никто не отметился». Обычный `GetTodayAttendanceAsync`, которым пользуются `/list` и перенос
на сайт, архив по-прежнему не показывает.

У `Notification` есть поле `Messenger`. Студенту, привязавшему оба мессенджера,
`StudentScheduleBackgroundJob` создаёт по уведомлению на каждый, и кнопка приходит в оба. Отметка
при этом засчитывается один раз: `MarkAttendanceAsync` обновляет существующую запись, а на
повторное нажатие бот отвечает, что студент уже отмечен.

## Основные сценарии

### Регистрация

Студент пишет `/start`, видит список тех, кто ещё не привязал **этот** мессенджер, и вводит свой
номер. Номер записывается в `TelegramId` или `VkId` — в зависимости от того, откуда пришло
сообщение. Поэтому студент, зарегистрированный в телеграме, увидит себя в списке во ВКонтакте
и может привязать второй аккаунт к той же записи. `null` в этих полях означает «не привязан»,
именно на это опираются выборки незарегистрированных.

### Отметка на паре

1. `StudentScheduleBackgroundJob` находит занятия, у которых наступило время начала, и заводит
   уведомления для подходящих студентов — по одному на каждый привязанный мессенджер.
   Уведомления не создаются после дедлайна и не дублируются в пределах дня.
2. `NotificationSenderBackgroundJob` собирает текст и отправляет сообщение с кнопкой.
3. Студент нажимает кнопку. Обработчик проверяет, что кнопка его, что дедлайн не прошёл и что
   занятие действительно есть в расписании на сегодня, после чего создаёт `Attendance` и убирает
   кнопку. Если занятия сегодня нет — сообщает об этом и тоже убирает кнопку.

Отметиться за пару другой подгруппы можно командой `/attend_other_group` — она показывает занятия
соседней подгруппы на сегодня.

### Отчёт старосте

После дедлайна `LeaderBackgroundJob` заводит отчёт каждому старосте в каждый привязанный им
мессенджер, если сегодня отчёт туда ещё не заводился. Тот же отчёт староста может получить в любой
момент командой `/list` — тогда он формируется на лету, без записи в очередь.

### Загрузка расписания и списка группы

Команды `/parse_schedule` и `/parse_group_list` переводят старосту в режим ожидания текста.
Разбором занимаются `src/ParseSchedule/ScheduleParser.cs` и
`src/ParseGroupList/GroupListParser.cs`.

При перезаливке старые данные уезжают в архив в одной транзакции: расписание вместе с предметами,
отметками и связанными уведомлениями; список группы — вместе со студентами, их отметками,
уведомлениями и записями старост. Привязки мессенджеров и подгруппы студентов, оставшихся
в новом списке, переносятся по совпадению ФИО, права старост восстанавливаются по ФИО или номеру.
Старосту, который сам не нашёлся в новом списке, бот не даст себя вычеркнуть — список не обновится.

### Права старосты

Основные старосты и администраторы задаются в конфиге списками айди отдельно для каждого
мессенджера. `ILeaderService` (`src/Services/Impl/LeaderService.cs`) сводит это воедино: основной
староста берётся из конфига, помощники — из таблицы `leader`, и права одинаково работают в обоих
мессенджерах. Основного старосту через бота снять нельзя, только через конфиг.

### Подгруппы

`GroupSettings.HasSubgroups` включает и выключает деление группы. Когда деление выключено, команды
`/set_subgroup`, `/remove_subgroup` и `/attend_other_group` скрыты из меню и не выполняются,
а подгруппы студентов сбрасываются. Студент без подгруппы получает уведомления о парах обеих.

## Перенос отметок на сайт

`AttendanceSyncBackgroundJob` включается настройкой `SiteSettings:MarkAttendanceOnSite`. Задача
собирает из базы отметки за сегодня, превращает их в список занятий с ФИО присутствующих и передаёт
вместе с учётными данными в приватный пакет `GroupListNet.Addons` (`IMarker`) — вся работа
с браузером и селекторами сайта закрыта там. Приложение знает только адреса из конфига.

## Особенности ВКонтакте

Ограничения API закрыты в `src/Bot/Clients/VkKeyboardBuilder.cs`:

- под сообщением помещается не больше шести кнопок, поэтому длинные списки студентов
  (`/add_leader`, `/remove_leader`, `/attend_other_group`) показываются обычной одноразовой
  клавиатурой — не больше десяти рядов по пять кнопок;
- подпись кнопки обрезается до 40 символов, всплывающий ответ — до 90;
- разметки нет, символы markdown из текста убираются;
- изменить только клавиатуру нельзя, нужен текст сообщения. Текст сообщения с кнопкой ВКонтакте
  в событии не присылает, поэтому там кнопка иногда остаётся — обработчик рассчитан
  на повторное нажатие.

## Время

Дедлайн отметки (`SendingSettings:DeadlineTime`) задаётся и сравнивается **в UTC**, а время начала
пар в расписании хранится **по МСК**: `StudentScheduleBackgroundJob` переводит текущий момент
в GMT+3, прежде чем искать начавшиеся занятия. В справке `/help` дедлайн показывается студенту
пересчитанным в МСК.

## Конфигурация

Секции читаются напрямую через `IConfiguration.GetSection(...).Get<T>()`, модели лежат
в `src/ConfigModels`: `TelegramSettingsConfiguration`, `VkSettingsConfiguration`, `SendingSettings`,
`SiteSettings`. В Docker значения приходят переменными окружения с двойным подчёркиванием вместо
двоеточия. Полный список настроек с пояснениями — в `README.md` и `.env.example`.

Мессенджер считается выключенным, если не задан его токен: клиент сообщает об этом в лог, а его
задача приёма сообщений не стартует. Так система поднимается только с телеграмом, только
со ВКонтакте или с обоими сразу.

## Тесты

`GroupListNet.Core.Tests` на xUnit, запуск — `dotnet test GroupListNet.sln`.

- `src/ParseGroupList/GroupListParserTests.cs` — разбор списка группы.
- `src/Bot/BotUpdateHandlerTests.cs` — логика команд на базе в памяти: регистрация в каждом
  мессенджере, привязка обоих аккаунтов к одному студенту, отметка и её однократность, дедлайн,
  права старосты.
- `src/Bot/NotificationMessageBuilderTests.cs` — сборка текста уведомлений, в том числе отчёта
  после ухода данных в архив.
- `src/Bot/VkKeyboardBuilderTests.cs` — раскладка клавиатуры под ограничения ВКонтакте.

Инфраструктура тестов — `src/Bot/BotTestHost.cs` (настоящие репозитории и сервисы поверх
`UseInMemoryDatabase`), `RecordingMessengerClient` вместо транспорта и `RowVersionInterceptor`,
который заполняет `Version`: в бою это делает PostgreSQL, а провайдер в памяти так не умеет.
