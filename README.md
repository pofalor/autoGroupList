# GroupListNet — телеграм-бот учёта посещаемости

Бот помогает старосте вести учёт посещаемости группы: рассылает студентам уведомления о начале пар,
собирает отметки «я на паре», в конце дня присылает старосте список отметившихся и (по желанию)
переносит отметки на сайт.

## Возможности

- Регистрация студента по номеру в списке группы.
- Автоматические уведомления о начале занятия с кнопкой «Я на паре».
- Ежедневный отчёт старосте и отчёт по запросу (`/list`).
- Загрузка расписания и списка группы через бота (команды старосты).
- Настройка деления группы на подгруппы: если деления нет, команды подгрупп скрываются.
- Основной староста задаётся в конфиге и может назначать помощников с такими же правами.
- Опциональный перенос отметок на сайт (браузерная автоматизация вынесена в отдельный
  NuGet-пакет [`GroupListNet.AttendanceSync`](https://www.nuget.org/packages/GroupListNet.AttendanceSync)).

## Состав решения

| Проект | Назначение |
| --- | --- |
| `GroupListNet` (`GroupListNet.Web.Api`) | Хост приложения: ASP.NET Core, точка входа, конфигурация, миграции |
| `GroupListNet.Core` | Бизнес-логика: телеграм-бот, фоновые задачи, сущности, репозитории, парсеры |
| `GroupListNet.Utils` | Расширения общего назначения |
| `GroupListNet.Core.Tests` | Модульные тесты |

Фоновые задачи (`GroupListNet.Core/src/BackgroundJobs`):

- `TelegramBotBackgroundJob` — обработка команд бота и отправка накопленных уведомлений;
- `StudentScheduleBackgroundJob` — создание уведомлений о начавшихся парах;
- `LeaderBackgroundJob` — ежедневный отчёт старосте после дедлайна;
- `AttendanceSyncBackgroundJob` — перенос отметок на сайт (запускается, только если включена настройка). Задача собирает из БД, кого и на каких занятиях надо отметить, и передаёт это в пакет `GroupListNet.AttendanceSync`, который и выполняет работу в браузере.

## Развёртывание в Docker

### Требования

- Docker 24+ с плагином Docker Compose.
- Токен телеграм-бота от [@BotFather](https://t.me/BotFather).
- Телеграм id того, кто разворачивает систему (узнать можно у [@userinfobot](https://t.me/userinfobot)).

### Шаги

1. Склонируйте репозиторий и перейдите в его корень.

2. Создайте файл `.env` из шаблона и заполните значения:

```bash
cp .env.example .env
```

Обязательные переменные: `POSTGRES_PASSWORD`, `TELEGRAM_BOT_TOKEN`, `LEADER_TELEGRAM_IDS`.
Полный список с пояснениями — в `.env.example`.

3. Соберите и запустите:

```bash
docker compose up -d --build
```

Compose поднимет два контейнера: `grouplist-db` (PostgreSQL 16) и `grouplist-bot` (приложение).
Миграции базы применяются автоматически при старте приложения, отдельная команда не нужна.

Если отметка на сайте не нужна (`MARK_ATTENDANCE_ON_SITE=false`), образ можно собрать без
браузера — сборка пройдёт быстрее, а образ будет примерно на 500 МБ легче:

```bash
docker compose build --build-arg INSTALL_CHROMIUM=false app
```

4. Проверьте, что всё поднялось:

```bash
docker compose ps
```

```bash
docker compose logs -f app
```

5. Напишите боту `/start` с того аккаунта, чей id указан в `LEADER_TELEGRAM_IDS`, и зарегистрируйтесь
   по номеру в списке группы. После этого станут доступны команды старосты.

### Управление

Остановить, не удаляя данные:

```bash
docker compose stop
```

Перезапустить после изменения `.env`:

```bash
docker compose up -d
```

Обновить приложение после изменения кода:

```bash
docker compose up -d --build app
```

Удалить контейнеры вместе с базой и логами (данные будут потеряны):

```bash
docker compose down -v
```

### Данные и логи

- База лежит в томе `db-data`, логи NLog — в томе `app-logs`.
- Посмотреть логи файлом: `docker compose exec app ls /app/logs`.
- Резервная копия базы:

```bash
docker compose exec db pg_dump -U postgres grouplist > backup.sql
```

## Конфигурация

Настройки читаются из `GroupListNet/appsettings.json`, а в Docker переопределяются переменными
окружения. Разделитель секций в переменных — двойное подчёркивание, например
`SiteSettings__MarkAttendanceOnSite`.

| Настройка | Переменная в `.env` | Описание |
| --- | --- | --- |
| `ConnectionStrings:DefaultConnection` | складывается из `POSTGRES_*` | Строка подключения к PostgreSQL |
| `TelegramSettings:TelegramBotToken` | `TELEGRAM_BOT_TOKEN` | Токен бота |
| `TelegramSettings:LeaderTelegramIds` | `LEADER_TELEGRAM_IDS` | Телеграм id основных старост через запятую |
| `TelegramSettings:AdminTelegramIds` | `ADMIN_TELEGRAM_IDS` | Телеграм id администраторов через запятую |
| `SendingSettings:DeadlineTime` | `DEADLINE_TIME` | До какого времени (UTC) можно отмечаться |
| `SiteSettings:MarkAttendanceOnSite` | `MARK_ATTENDANCE_ON_SITE` | `true` — переносить отметки на сайт, `false` — не переносить |
| `SiteSettings:Username` / `Password` | `SITE_USERNAME` / `SITE_PASSWORD` | Учётные данные для сайта, нужны только при `true` |
| `SiteSettings:ChromeBinaryPath` | задаётся в `docker-compose.yml` | Путь до браузера; в образе это `/usr/bin/chromium` |
| `SiteSettings:ChromeDriverDirectory` | задаётся в `docker-compose.yml` | Каталог с `chromedriver`; в образе это `/usr/bin` |

### Отметка на сайте

При `MarkAttendanceOnSite=false` задача `AttendanceSyncBackgroundJob` не запускается: бот собирает
отметки только в своей базе, логин и пароль от сайта не нужны. При `true` в контейнере используется
системный, который ставится в образ вместе с драйвером — их версии согласованы между собой.

Сама работа с сайтом (адреса, селекторы, порядок логина) закрыта в приватном пакете
`GroupListNet.AttendanceSync`. Основное приложение только передаёт ему список занятий, ФИО
присутствующих и учётные данные из `SiteSettings`; адреса сайта остаются в конфигурации.
Каталог с драйвером берётся из `SiteSettings:ChromeDriverDirectory`, а если он пуст —
драйвер скачивается автоматически.

### Права старосты

- Основным старостой становится тот, чей телеграм id указан в `LeaderTelegramIds`. Права выдаются
  автоматически при старте приложения и при регистрации такого пользователя в боте.
- Основной староста назначает помощников командой `/add_leader` и снимает их `/remove_leader`.
  У помощников те же права, включая назначение других помощников.
- Основного старосту нельзя снять через бота — только изменив конфиг.
- Чтобы получать ежедневный отчёт, староста должен быть зарегистрирован в боте как студент группы.

## Команды бота

Для всех студентов:

| Команда | Что делает |
| --- | --- |
| `/start` | Регистрация или приветствие |
| `/schedule` | Расписание на сегодня |
| `/info` | ФИО, номер в группе, подгруппа |
| `/help` | Справка по доступным командам |

Если группа делится на подгруппы, дополнительно доступны `/set_subgroup`, `/remove_subgroup` и
`/attend_other_group`. Когда деление выключено, эти команды скрыты и не выполняются.

Для старосты и его помощников:

| Команда | Что делает |
| --- | --- |
| `/list` | Список отметившихся за сегодня |
| `/parse_schedule` | Загрузить новое расписание (пересылкой от [@knrtukaibot](https://t.me/knrtukaibot)) |
| `/parse_group_list` | Загрузить новый список группы |
| `/subgroups` | Задать, делится ли группа на подгруппы |
| `/add_leader` | Назначить помощника старосты |
| `/remove_leader` | Снять помощника старосты |

Для администраторов: `/time` — текущее время сервера (аналог ping).

При смене списка группы связанные со студентами записи уходят в архив (помечаются удалёнными),
а телеграм-регистрации студентов, оставшихся в списке, сохраняются по ФИО.

## Запуск без Docker

Требуется .NET SDK 8.0+ и PostgreSQL 16.

1. Создайте базу и пропишите строку подключения в `GroupListNet/appsettings.Development.json`.
2. Заполните `TelegramSettings` и `SiteSettings` в том же файле.
3. Запустите:

```bash
dotnet run --project GroupListNet/GroupListNet.Web.Api.csproj
```

Сборка и тесты:

```bash
dotnet test GroupListNet.sln
```

Новая миграция после изменения сущностей:

```bash
dotnet ef migrations add ИмяМиграции --project GroupListNet.Core --startup-project GroupListNet
```

## Безопасность

Секреты (токен бота, пароли) держите в `.env` — он добавлен в `.gitignore`. Значения, лежащие в
`appsettings.json`, попадают в собранный образ, поэтому для боевого развёртывания задавайте их
переменными окружения.
